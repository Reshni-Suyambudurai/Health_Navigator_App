# Backend Architecture Rules

## Request Flow
```
Client → Routes → Services → Repositories → Models → PostgreSQL
```

## File Placement

- **Routes**: `app/api/routes/{entity}_routes.py`
- **Services**: `app/services/{entity}_service.py`
- **Repositories**: `app/database/repositories/{entity}_repository.py`
- **Models**: `app/database/models/{entity}.py`
- **Exceptions**: `app/core/exceptions.py`
- **Response Models**: `app/core/response_models.py`

## Rules by Layer

**Routes** - HTTP only
- ✅ Return `SuccessResponse(status, message, data)`
- ✅ Call service methods
- ❌ NO business logic, NO database queries

**Services** - Business logic
- ✅ Raise custom exceptions (AuthenticationException, NotFoundException, etc.)
- ✅ Use bcrypt for passwords
- ❌ NO HTTPException, NO direct DB queries

**Repositories** - Database only
- ✅ CRUD methods: `find_by_id()`, `find_all()`, `save()`, `delete()`
- ❌ NO business logic

**Models** - Table definitions
- ✅ SQLAlchemy columns and relationships
- ❌ NO methods or logic

## Exception Types
- `AuthenticationException` - Invalid credentials (401)
- `AuthorizationException` - Access denied (403)
- `NotFoundException` - Resource not found (404)
- `ValidationException` - Invalid input (400)
- `ConflictException` - Duplicate resource (409)

## Response Format

**Success**: `SuccessResponse(status="success", message="...", data={...})`
**Error**: Raised exception auto-converts to `ErrorResponse`

## Adding Feature
1. Model → 2. Repository → 3. Service → 4. Routes → 5. Register in main.py
